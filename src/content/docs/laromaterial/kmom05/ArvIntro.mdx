## Vad är arv (inheritance)?

**Arv** innebär att en klass kan återanvända egenskaper (attribut) och metoder från en annan klass. Man kan se det som att en ny klass bygger vidare på en befintlig klass istället för att börja från början.

Det kan också kallas **specialisering** eller **utökning (extension)**. En basklass beskriver sådant som flera objekt har gemensamt, medan en subklass lägger till sådant som är specifikt för just den typen av objekt.

Till exempel kan klassen Person innehålla egenskaper som namn och ålder. Klassen Student kan sedan ärva från Person och dessutom ha studentrelaterad information, till exempel program eller registrerade kurser.

**Med arv får vi:**

- **Gemensam kod** som kan återanvändas i flera klasser.
- **Tydlig struktur** där relaterade klasser organiseras i en hierarki.
- **Möjlighet att specialisera beteende** genom att lägga till nya metoder eller ändra hur ärvda metoder fungerar.
- **Mindre duplicerad kod**, eftersom gemensam funktionalitet bara behöver skrivas en gång.
- **Enklare underhåll**, eftersom förändringar i basklassen automatiskt kan komma alla subklasser till nytta.

## Basklass och subklass

När vi använder arv brukar vi tala om **basklasser** och **subklasser**.

- **Basklass** → den mer generella klassen som innehåller gemensamma egenskaper och metoder.
- **Subklass** → en mer specifik klass som ärver från basklassen och kan lägga till egen funktionalitet.

En subklass ärver allt som finns i basklassen och kan sedan utökas med nya attribut och metoder.

### Exempel

Anta att vi vill beskriva olika sorters djur. Här är:

- Animal en basklass.
- Dog och Cat är subklasser.

Alla djur kanske har ett namn och kan göra ljud ifrån sig, så detta placeras i basklassen Animal.

Hundar och katter har dessutom egna egenskaper:

- En Dog kanske kan vakta.
- En Cat kanske kan spinna.

#### Tumregel

En subklass ska alltid kunna beskrivas som en mer specifik variant av basklassen.

Vi kan säga:

- En hund är ett djur.
- En katt är ett djur.

Det låter naturligt, vilket gör arv lämpligt.

Däremot låter det inte naturligt att säga:

- Ett hjul är en bil.

Därför bör Wheel inte ärva från Car. Där handlar det istället om att en bil har hjul, vilket är ett exempel på komposition.

**Minnesregel:** Arv används när relationen är är en ("is-a"), medan komposition används när relationen är har en ("has-a").


## Relation

Vi repeterar de relationer vi redan kan. Dessa beskriver relationer mellan objekt:

- **Komposition**, den starkaste relationen, *har en/del av (äger)* och bestämmer över det andra objektets livscykel. När det ägande objektet upphör att existera upphör även den del som det äger.
- **Aggregation**, en svagare relationen, *har en (äger inte)*. Det andra objektet kan fortsätta att existera om det första objektet upphör att existera.
- **Association**, *känner till eller använder* ett annat objekt

När det gäller arv pratar vi om relationen *är en* och det är en relation mellan klasser.

Vi kan till exempel säga att:

- En hund är ett djur.
- En katt är ett djur.

Vi har klassen Animal och klasserna Dog och Cat. Om vi använder arv kan ett objekt av klassen Dog eller Cat behandlas som ett objekt av typen Animal. Vi kan skapa en lista med husdjur `List<Animal> pets`. Listan `pets` kan innehålla referenser av typen Animal, men objekten som lagras i listan kan vara instanser av både Dog och Cat.

**Det viktiga med arv är att ett objekt av en subklass kan användas där ett objekt av basklassen förväntas.**

Så här kan basklassen Animal med sina subklasser Dog och Cat se ut:

```csharp title="Exempel basklassen Animal"
public class Animal
{
    private string _name;

    public Animal(string name)
    {
		this._name = name;
    }

	public string GetName()
	{
		return this._name;
	}

    protected void SetName(string newName)
	{
		this._name = newName;
	}

    public void Eat()
    {
        Console.WriteLine("Animal eats");
    }
	
	public virtual void ShowInfo()
	{
		Console.WriteLine($"Name: {this._name}");
	}

    public virtual void MakeSound()
    {
        Console.WriteLine("Some animal sound");
    }
}
```

```csharp title="Exempel subklassen Dog"
public class Dog : Animal
{
	private bool _isTrained;

	public Dog(string name, bool isTrained) : base(name)
    {
        this._isTrained = isTrained;
    }

	public override void ShowInfo()
    {
        string info = "The dog is trained.";

        base.ShowInfo();
        if ( ! this._isTrained)
        {
            info = "The dog is not yet trained.";
        }
        Console.WriteLine(info);
    }

    public override void MakeSound()
    {
        Console.WriteLine("Woof!");
    }
}
```

```csharp title="Exempel subklassen Cat"
public class Cat : Animal
{
    private static int _catCounter = 0;

    public Cat(string name) : base(name)
    {
        Cat._catCounter++;
    }

    public static int GetNoOfCats()
    {
        return Cat._catCounter;
    }

    public override void MakeSound()
    {
        Console.WriteLine("Meow!");
    }
}
```

Notera att `public class Dog : Animal` beskriver att klassen Dog ärver av klassen Animal.

När ett objekt av klassen Dog skapas `public Dog(string name, string breed) : base(name)` så anropas först basklassens konstruktor och basklassens attribut `_name` til `name` sätts. Därefter sätts subklassens attribut `_breed` till `breed`. Trots att vi använder både basklassens konstruktor och subklassens konstruktor så skapas bara ett objekt.

När ett Dog-objekt skapas får först basklassen Animal bygga sin del av objektet via base(name). Därefter får klassen Dog bygga sin egen del av objektet. Parametrarnas ordning i subklassens konstruktor spelar ingen roll för arvsmekanismen. Det viktiga är att rätt värde skickas vidare till basklassens konstruktor med base(...).

Basklassen har en metod `SetName()` som har åtkomstnivå **protected** och det innebär att bara basklassens subklasser, i detta fallet klasserna Dog och Cat kan komma åt metoden `Set Name()`. Den kan då anropas inuti en metod i basklassen med `bas.SetName("New name").

```csharp title="Test av basklassen och subklasserna i Program.cs"
Dog dog = new Dog("Buster", false);
dog.Eat();   // från Animal
// Ger utskriften: Animal eats
dog.ShowInfo();  // från Dog
// Ger utskriften: Name: Buster
// The dog is not yet trained.
dog.MakeSound();  // från Dog
// Ger utskriften: Woof!
```

## Polymorfism

**Polymorfism** betyder "många former". Inom objektorienterad programmering innebär det att objekt av olika klasser kan behandlas som objekt av samma basklass.

Du kan ha en lista av typen Animal, men den kan innehålla både hundar och katter eftersom både Dog och Cat ärver från Animal:

```csharp title="Exempel på lista av typen Animal, kod från Program.cs"
List<Animal> animals = new List<Animals>();

animals.Add(new Dog("Fido", true));
animals.Add(new Cat("Misse"));

```

Om flera klasser ärver från samma basklass kan de ge egna implementationer av samma metod. När metoden anropas avgör objektets verkliga typ vilken implementation som ska köras.

Detta gör det möjligt att skriva kod som arbetar mot en gemensam basklass istället för mot varje enskild subklass, vilket ofta leder till mer flexibel och lättunderhållen kod.

**virtual** används i basklassen för att markera att en metod får omdefinieras i en subklass. **override** används i subklassen för att ersätta basklassens implementation med en egen version.

Detta gör det möjligt för olika objekt att reagera olika på samma metodanrop. Ta metoden MakeSound() som exempel. I basklassen är metoden markerad med virtual, vilket innebär att subklasserna får ändra dess beteende, men de måste inte göra det.

I exemplet ovan har både Dog och Cat valt att använda override för att ge MakeSound() ett beteende som passar respektive djur. När metoden anropas kommer därför en hund att skälla och en katt att jama, trots att båda anropas genom samma metodnamn.

Tack vare polymorfism kan vi behandla alla objekt i listan som Animal, samtidigt som varje objekt kan använda sitt eget beteende.

```csharp title="Exempel på hur metoden MakeSound anropas, kod från Program.cs"
...
foreach (Animal animal in animals)
{
    animal.MakeSound();
}

// Ger utskriften:
// Woof!
// Meow!
```

Rätt metod väljs automatiskt när programmet körs. Om objektet är av typen Dog anropas metoden i Dog. Om klassen inte har någon egen implementation används istället metoden från basklassen Animal.

### Två huvudtyper av polymorfism (överkurs)

1. Statisk polymorfism (Kompileringstid)  
Uppnås genom metodöverlagring (method overloading). Det innebär att du har flera metoder med samma namn men med olika parametrar (antal eller datatyp) i samma klass. C# avgör vilken metod som ska köras baserat på vilka argument du skickar in.
2. Dynamisk polymorfism (Körtid)  
Uppnås genom att överskugga en metod (method overriding). Du låter en subklass ärva från en basklass och skriva om en specifik metod för att passa dess behov. Detta görs med nyckelorden **virtual** (i basklassen) och **override** (i subklassen)


## base

**base** används för att anropa basklassens konstruktor eller metoder i basklassen och därmed återanvända dess funktionalitet.

## För- och nackdelar

### Fördelar

- Kodåteranvändning - Gemensamma attribut och metoder kan placeras i basklassen och ärvs automatiskt av subklasserna.
- Polymorfism - Objekt av olika subklasser kan behandlas som objekt av samma basklass, samtidigt som de kan ha olika beteenden genom virtual och override.
- Tydlig modellering/struktur, Arv passar när relationen är en stämmer. Exempelvis är en Dog ett Animal.
- Typkontroll vid kompilering. Kompilatorn kan verifiera att arvshierarkin används korrekt. Exempel: `Animal animal = new Dog("Rex", false);` funkar eftersom Dog ärver Animal.
- Bra språkstöd. C# har inbyggt stöd för arv, polymorfism, abstrakta klasser och virtuella metoder.

### Nackdelar

- Endast en basklass (single inheritance). En klass kan bara ärva från en annan klass.
- Hård koppling. Subklasser är beroende av basklassen. Ändringar i basklassen kan påverka många andra klasser.
- Risk för felaktig design. Arv används ibland där komposition hade varit bättre. Exempel: class Car : Engine // fel men det borde vara: Car har en Engine (komposition)
- Djupa arvshierarkier med många nivåer kan göra koden svår att förstå och ändra.

### Använd arv i OOP

- tydlig “är en”‑relation
- gemensam data + beteende
- behov av polymorfism

## Sammanfattning

- **Arv** beskriver relationen är en.
- **virtual** betyder att en metod får omdefinieras.
- **override** används för att omdefiniera metoden i en subklass.
- **base** används för att anropa basklassens konstruktor eller metoder.
- **Polymorfism** gör att samma kod kan användas för olika typer av objekt.
